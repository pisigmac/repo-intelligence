## Identifications / Recommendations

1. **Language gaps still produce `unknown` for common dotfiles and modern extensions.**
   - Examples: `.eslintignore`, `.npmignore`, `.editorconfig`, `.dockerignore`, `.prettierignore`, `.gitattributes`, `CITATION.cff`, `.github/CODEOWNERS`, `.mjs`, `.cjs`, `.gql`/`.graphql`, `.snap`/`.ambr`, `.svg`, `.lock`, `.txt`, `.pyi`.
   - Recommendation: add these to `EXTENSION_MAP` / `FILENAME_MAP` in `services/parser/language.py` and map dotfiles that are config/ignore files to `config` or `gitignore`.

2. **Directory imports (`".."`, `"../"`, `"./app.module"`) are often flagged as unresolved even when a valid `index.*` or `<name>.*` exists.**
   - This is partly because the anomaly check uses a naive stem match, but it also exposes that the resolver has no special handling for package-root directory imports.
   - Recommendation: improve `_resolve_candidate` to treat `".."` / `"../"` as package-root lookups and add a more robust resolved-or-not check to the reporting script.

3. **Anonymous callbacks in route definitions are not captured as functions.**
   - Express test files match the route pattern (`app.get(...)`) but contain only anonymous `function(req, res){...}` callbacks, so `functions` is empty.
   - Recommendation: optionally extract anonymous function expressions used as route/callback arguments.

4. **Decorator-based TypeScript (NestJS) is under-parsed.**
   - Controllers/services are detected by keyword heuristics, but class methods with decorators (`@Get()`, `@Post()`) and class property injection are not extracted.
   - Recommendation: add decorator parsing for TS classes to capture routes, injected dependencies, and provider metadata.

5. **Python cross-package imports rarely produce local graph edges.**
   - In the Langchain monorepo, Python imports are package-absolute (e.g., `from langchain_core.prompts ...`), so the file-level dependency graph has 0 edges.
   - Recommendation: for Python monorepos, build a package-to-file index so absolute package imports can be resolved to the local file that defines the package.

6. **Classification heuristics can mislabel large `__init__.py` re-export files as `middleware` or `controller`.**
   - These files often contain only `from .foo import Bar` re-exports and no real logic.
   - Recommendation: add a re-export-only heuristic that classifies such files as `utility` or `index`.
